# Statistical Rules for Knowledge Alignment Results v1.0

## 1. Scope of Application

These rules are used to compare the `knowledge_alignment.yaml` files generated by multi-round knowledge alignment agents, with a focus on quantifying:

- the scale of structured knowledge representation;
- evidence coverage and source composition;
- knowledge expansion for domain experts and computer experts;
- internal connections among knowledge objects;
- the degree of operationalization of computational proxy indicators and reward thresholds.

These statistics reflect the **scale, connectivity, and degree of operationalization of knowledge representation**, and do not directly represent the scientific correctness of the knowledge. Whether advantageous scaffolds, computational proxies, and reward thresholds are scientifically valid still requires certification by the corresponding experts.

### 3.2 Extended Knowledge Object Audience Distribution

### 3.3 Evidence Service Audience Coverage

The current `evidence` objects do not have a direct `audience` field. Therefore, “evidence audience” is calculated using the **reference propagation rule**:

1. Identify the knowledge objects that reference a particular piece of evidence;
2. Assign one or more service audiences to the evidence according to the audience of the referencing objects;
3. The same piece of evidence can serve multiple audiences simultaneously, so the sum of the three columns may exceed the total number of evidence objects.

Object-to-audience mapping rules:

| Object Referencing Evidence | Evidence Audience |
|---|---|
| `concepts` | `shared` |
| `claims` | `shared` |
| `indicators` | Use `indicators[].audience` |
| `scaffold_families` | `domain_expert` |
| `computational_proxy_indicators` | `computer_expert` |

Statistical results:

| Evidence Service Audience | First Round | First-Round Proportion of Evidence Objects | Second Round | Second-Round Proportion of Evidence Objects |
|---|---:|---:|---:|---:|
| `shared` | 15 | 100.0% | 15 | 75.0% |
| `domain_expert` | 3 | 20.0% | 13 | 65.0% |
| `computer_expert` | 3 | 20.0% | 9 | 45.0% |
| Total number of evidence objects | 15 | — | 20 | — |

Notes:

- This is a **multi-label coverage statistic**, not a mutually exclusive classification;
- The evidence newly added in the second round serves advantageous scaffolds and computational proxies to a greater extent, so domain/computer coverage increased significantly;
- To achieve completely inference-free statistics in the future, the following should be added to `evidence`:

```yaml
audience:
  - shared
  - domain_expert
  - computer_expert
```

### 4.2 Paper Evidence Location Levels

“Full-text location evidence” is not an independent source type, but a quality subset of `paper` evidence.

In these statistics, evidence is counted as having an exact full-text location if it meets either of the following conditions:

- `location` contains `source lines`;
- or there is an explicit page number, table, figure, supplementary material, or data-row location.

The current data uses `source lines` as the basis for determination.

| Paper Evidence Location Level | First Round | Second Round |
|---|---:|---:|
| Paper evidence objects with a specific full-text location | 7 | 7 |
| Paper evidence objects with only paper/knowledge-page-level location | 3 | 7 |
| **Total number of paper evidence objects** | **10** | **14** |
| Exact full-text location rate | **70.0%** | **50.0%** |

Note: The number of paper evidence objects increased in the second round, but many of the newly added pieces of evidence are located only at the llm-wiki concept-page level and have not yet been traced back to specific page numbers, figures, tables, or source-text lines in the original papers.

### 4.3 Number of Unique Source Documents

The number of evidence objects is not equal to the number of source papers. The same paper can produce multiple evidence objects.

Deduplication key:

```text
source_type + identifier_or_url
```

Statistical results:

| Unique Source | First Round | Second Round | Increment |
|---|---:|---:|---:|
| Number of unique paper sources | 9 | 11 | +2 |
| Number of unique ontology/authoritative terminology sources | 5 | 6 | +1 |

It is recommended that papers report both of the following:

- `number of paper evidence objects`: indicates how many pieces of structured evidence were formed from papers;
- `number of unique paper sources`: indicates how many different papers were actually used.

The two must not be used interchangeably.

| Reward component → knowledge object | 0 | 19 |
| **Total number of valid internal references** | **114** | **201** |

All references counted in both rounds can be resolved to valid target IDs, so the current internal reference validity rate is 100% for both rounds.

### 5.2 Scope of Reference Fields

The statistical program scans only the following fields:

```yaml
reference_fields:
  - concepts[].evidence
  - indicators[].evidence
  - indicators[].related_indicators
  - claims[].evidence
  - scaffold_families[].evidence
  - computational_proxy_indicators[].evidence
  - computational_proxy_indicators[].linked_endpoints
  - optimization_targets.*
  - reward_design.components.*
```

### 5.3 Reference Edge Deduplication Rule

A reference edge is uniquely determined by the following triple:

```text
source_object_id + reference_field + target_object_id
```

For example:

```text
CP001 + linked_endpoints + I007
```

is one reference.

If the same piece of evidence is referenced by two different objects, it should be counted as two edges because they represent two different knowledge connections.

### 5.4 Conditions for a Valid Reference

A reference is counted in the “number of valid internal references” only if all of the following conditions are met:

1. The source object exists;
2. The target ID exists in the allowed object registry;
3. The target type complies with the field constraints;
4. The reference edge is not duplicated.

The following should be output simultaneously:

```text
total_reference_edges
valid_reference_edges
invalid_reference_edges
reference_validity_rate
```

## 6. Reward Threshold Statistics

### 6.1 Current Statistical Definition

A “proxy indicator with an explicit numerical reward threshold” is defined as:

> `computational_proxy_indicators[].initial_reward_rule` contains at least one explicit numerical comparison condition or numerical interval.

Of the 10 proxy indicators in the second round, 8 meet this condition. Therefore:

```text
Number of proxy indicators with explicit numerical reward thresholds = 8
Numerical reward threshold coverage = 8 / 10 = 80.0%
```

Proxy indicators containing numerical thresholds:

- CP001: absorption wavelength;
- CP002: oscillator strength;
- CP003: S1–Tn energy gap;
- CP004: SOC;
- CP005: T1 energy;
- CP006: S1–T1 energy gap;
- CP008: electron-transfer free energy;
- CP009: cLogP range.

Without a unified numerical threshold:

- CP007: HOMO/LUMO separation and charge-transfer characteristics;
- CP010: planarity and torsional degrees of freedom.

### 6.2 Current Automation Limitations

The current thresholds are stored in free text, for example:

```yaml
initial_reward_rule:
  pass: "lambda_max >= 650 nm"
  strong: "700-800 nm"
```

They can be identified semi-automatically using regular expressions, but ambiguities remain:

- Numerical values in the text are not necessarily reward thresholds;
- One indicator may have multiple thresholds;
- Different mechanistic routes may have opposite thresholds;
- A threshold may be a pass line, strong-reward line, saturation line, or penalty line;
- Some thresholds apply only to specific scaffolds or computational methods.

### 6.3 Recommended Structured Fields

It is recommended that this be changed to the following in subsequent versions:

```yaml
thresholds:
  - route: general
    level: pass
    metric: lambda_max
    operator: ">="
    value: 650
    unit: nm
    status: provisional
    basis: literature_and_expert_initialization
    evidence: [E016, E020]

  - route: general
    level: strong
    metric: lambda_max
    operator: between
    lower: 700
    upper: 800
    unit: nm
    status: provisional
```

After this, the following can be counted in a fully rule-based manner:

- the number of proxy indicators with thresholds;
- the total number of threshold entries;
- the number of thresholds for each mechanistic route;
- the number of expert-certified thresholds;
- the number of experimentally calibrated thresholds;
- the number of thresholds supported by evidence.

## 7. Field Definitions for Each Statistical Metric

| Statistical Metric | Included Fields | Deduplication Key | Fully Automatable | Boundary of Scientific Interpretation |
|---|---|---|---|---|
| Total number of structured knowledge objects | `concepts`, `indicators`, `claims`, `evidence`, `scaffold_families`, `computational_proxy_indicators` | Unique ID of each object | Yes | Reflects object scale and does not prove correctness |
| Number of evidence objects | `evidence[].evidence_id` | `evidence_id` | Yes | Does not prove that the evidence is sufficient or reliable |
| Number of advantageous scaffold objects | `scaffold_families[].scaffold_id` | `scaffold_id` | Quantity can be automated | “Advantageous” requires certification by domain experts |
| Number of computational proxy indicators | `computational_proxy_indicators[].proxy_id` | `proxy_id` | Quantity can be automated | Computability requires validation by computational experts |
| Number of valid internal references | Reference fields listed in Section 5.2 | Source ID + field + target ID | Yes | Reflects connectivity and does not prove that the relationship is reasonable |
| Number of indicators with explicit reward thresholds | `computational_proxy_indicators[].initial_reward_rule`; use `thresholds` in the future | `proxy_id` | Currently semi-automated; fully automated after structuring | Threshold rationality requires expert review and experimental calibration |
| Explicit indicator Audience | `indicators[].audience` | `indicator_id` | Yes | Covers only the original performance indicators |
| Extended knowledge object Audience | indicators + scaffold/proxy type mapping | Unique object ID | Automatable according to fixed rules | Currently partly inferred from object type |
| Evidence service audience coverage | Referenced evidence + audience of the referencing object | `evidence_id + audience` | Automatable according to fixed rules | Multi-label; cannot be summed as a total |
| Evidence source type | `evidence[].source_type` | `evidence_id` | Yes | Source type does not represent evidence quality |
| Number of unique paper sources | `identifier_or_url` of paper evidence | source_type + identifier_or_url | Yes | Different from the number of evidence objects |
| Number of pieces of evidence with an exact full-text location | `evidence[].location` | `evidence_id` | Currently rule-based; adding a dedicated field is recommended | Reflects only location precision |

## 8. Recommended New Fields

To reduce inference, it is recommended that the Skill add the following in subsequent versions:

```yaml
# All knowledge objects
audience:
  - shared
  - domain_expert
  - computer_expert

# Evidence
source_type: paper|ontology|experiment_report|calculation_report|database|expert
source_granularity: full_text_exact|paper_level|ontology_term|report_record|dataset_record
locator:
  page: null
  section: null
  table: null
  figure: null
  source_lines: null

# Computational proxy
thresholds: []
expert_status: pending|approved|revised|rejected
protocol_status: conceptual|specified|benchmarked
```

After these fields are added, Audience, full-text location, and reward thresholds can all be counted directly, without relying on object types or regular-expression inference from text.

## 9. Recommended Wording for the Paper

> The statistics are automatically generated based on the machine-readable `knowledge_alignment.yaml` produced in each round. The total number of structured knowledge objects is defined as the sum of the numbers of unique IDs across six object types: concepts, performance indicators, knowledge claims, evidence, advantageous scaffolds, and computational proxy indicators. A valid internal reference is defined as a unique directed reference edge that can be resolved to a valid target ID. Audience distributions are calculated separately based on explicit indicator annotations and propagation through evidence references; because a single piece of evidence may simultaneously support shared knowledge, domain knowledge, and computational knowledge, evidence Audience is measured using multi-label coverage rather than mutually exclusive proportions. Paper evidence is further divided into the number of evidence objects, the number of unique paper sources, and the number of pieces of evidence with a specific full-text location. A proxy indicator with an explicit reward threshold is defined as a computational proxy indicator containing at least one numerical comparison condition or numerical interval.

> These statistics are used to characterize the scale of knowledge representation, evidence composition, cross-expert coverage, semantic connectivity, and degree of computational operationalization; the scientific validity of advantageous scaffolds, computational proxies, and reward thresholds still requires further certification by domain experts, computational chemistry experts, and experimental data.
